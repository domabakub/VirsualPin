# ระบบเครื่องดนตรีในเครือ Next

สถานะ: แบบออกแบบสำหรับพัฒนาต่อ ยังไม่ได้เปลี่ยนระบบที่ใช้งานอยู่

## แนวทางผลิตภัณฑ์

ให้แต่ละเครื่องเป็นผลิตภัณฑ์ที่มีบุคลิกของตัวเอง แต่ใช้แพลตฟอร์มร่วมกัน เริ่มจากแอปและ repository เดียว แยกโมดูลตามเครื่องดนตรี ยังไม่จำเป็นต้องแยก deployment หรือ backend

ชื่อเครือชั่วคราว: **Next Instruments** เป็นข้อเสนอที่เปลี่ยนได้ ไม่ใช่ชื่อที่ยืนยันแล้ว

| เครื่อง | ชื่อผลิตภัณฑ์ | คำอธิบาย | รหัสถาวร | เส้นทาง |
| --- | --- | --- | --- | --- |
| พิณ | Phin Next | Virtual Phin | phin | /instruments/phin |
| ระนาด | Ranat Next | Virtual Thai Xylophone | ranat | /instruments/ranat |

ใช้ชื่อ Ranat Next เป็นแบรนด์ และ Virtual Thai Xylophone เป็นคำอธิบาย เพื่อสื่อว่าเป็นระนาดไทย แยกชื่อที่แสดงออกจากรหัสถาวร เปลี่ยนแบรนด์ในภายหลังได้โดยไม่ทำให้ข้อมูลเสียหาย

สมมติฐานสำหรับรุ่นแรก: เริ่มจากระนาดเอกหนึ่งชุดเสียง จำนวนลูกระนาด ช่วงเสียง และการเทียบเสียงต้องกำหนดจากชุดเสียงที่เลือกก่อนทำเนื้อหาเรียน ไม่ใช้การตั้งเสียงของพิณแทนโดยอัตโนมัติ

## ประสบการณ์ผู้ใช้

- หน้า / เป็นหน้ารวมเครื่องดนตรี มีการ์ด Phin Next และ Ranat Next พร้อมสถานะ พร้อมเล่น / ทดลอง / เร็ว ๆ นี้
- แต่ละผลิตภัณฑ์มีหน้าแนะนำ เล่นอิสระ คลังเพลง บทเรียน และบันทึกของฉันในรูปแบบเดียวกัน
- ส่วนหัวแสดงชื่อเครื่องปัจจุบันและตัวสลับเครื่อง ใช้ตัวอักษร ปุ่ม ระยะห่าง และโครงเมนูร่วมกัน พิณใช้สีหลักเดิม ระนาดเสนอสีอำพันกับภาพลูกระนาด
- แสดงเฉพาะความสามารถที่พร้อม เช่น ระนาดรุ่นแรกเล่นด้วยสัมผัสและคีย์บอร์ด ส่วนการตีผ่านกล้องแสดงว่าอยู่ระหว่างพัฒนา
- สลับเครื่องแล้วไปหน้าหลักของเครื่องปลายทาง ไม่ย้ายเพลงหรือโน้ตข้ามเครื่องโดยเงียบ ๆ หากกำลังอัดต้องจบหรือยกเลิกการอัดก่อน
- หน้าเพลงแสดง arrangement ของเครื่องนั้น เพลงชื่อเดียวกันใช้การเรียบเรียงคนละชุดได้

## โครงสร้างระบบ

แยกเป็นสามส่วน:

1. **Shared platform**: navigation, design tokens, metronome, clock, recording, playback scheduling, storage, ความก้าวหน้า และโครงบทเรียน
2. **Instrument registry**: รายการเครื่อง ชื่อ สี เส้นทาง สถานะ รุ่นข้อมูล และ capability ของแต่ละเครื่อง เป็นแหล่งข้อมูลเดียวให้หน้าเลือกเครื่องและเมนู
3. **Instrument module**: พื้นผิวเล่น การแปล input เป็นโน้ต การตั้งเสียง ตัวสร้างเสียง แบบฝึก และการตรวจโน้ตเฉพาะเครื่อง

โครงสร้างเป้าหมาย:

```text
src/
  app/instruments/[instrumentId]/
    layout.tsx
    page.tsx
    play/[slug]/page.tsx
    songs/page.tsx
    takes/page.tsx
    takes/[id]/page.tsx
    takes/[id]/practice/page.tsx
    studio/page.tsx
  instruments/
    registry.ts
    contracts.ts
    phin/       # surface, input, tuning, audio, curriculum
    ranat/      # surface, input, tuning, audio, curriculum
  components/platform/
  lib/platform/ # events, scheduling, recording, storage, practice
```

Registry เก็บ metadata ที่ serializable ส่วน client runtime ใช้ตาราง loader แบบ explicit เพื่อโหลดเฉพาะเครื่องที่เปิด ไม่ประกอบ import path จาก URL ผู้ใช้ ตรวจ instrumentId กับ registry และคืน not-found เมื่อไม่รู้จัก Route รับ params ตามคู่มือ Next.js ที่ติดตั้งในโปรเจกต์

### สัญญาระหว่างโมดูล

Registry ของเครื่องต้องระบุ id, brandName, description, status, theme, defaultTuningId และ capabilities ได้แก่ touch, keyboard, camera, recording, lessons, studio, pitchBend พร้อมทั้ง loader ของ runtime แยกต่างหาก

Runtime ต้องรองรับ:

- prepare: เตรียมเสียงหลังผู้ใช้เริ่มเล่น พร้อมสถานะโหลดและข้อผิดพลาด
- resolveTarget: แปลงตำแหน่งที่เล่นเป็น pitch ตาม tuning ที่เลือก
- trigger / release: เล่นและหยุด voice ตาม event id รองรับหลายโน้ตพร้อมกัน
- stopAll / dispose: หยุดเสียง ยกเลิกงานที่นัดไว้ และคืนทรัพยากรเมื่อออกจากเครื่อง
- validateTarget: ตรวจตำแหน่งเล่นก่อนใช้ข้อมูลที่บันทึกหรือนำเข้า

การเปลี่ยนเครื่องต้องหยุด recorder, scheduled voices และ input listeners เดิม กล้องใช้ capture/tracking ร่วมกันได้ แต่ตัวตรวจท่าตีหรือดีดเป็นของแต่ละเครื่อง

## ข้อมูลโน้ตที่รองรับหลายเครื่อง

ปัจจุบัน src/data/songs.ts, src/lib/takes/types.ts และ src/lib/studio/types.ts ใช้ string/fret ขณะที่ usePhinAudio และ phinTuning แปลตำแหน่งเป็นเสียงพิณโดยตรง จึงต้องแยก “โน้ตดนตรี” ออกจาก “ตำแหน่งที่เล่น”

สัญญาข้อมูลรุ่น 2:

| ส่วน | ข้อมูล |
| --- | --- |
| Recording / arrangement | schemaVersion, id, instrumentId, instrumentVersion, tuningSnapshot, notes |
| โน้ตร่วม | id, onsetMs, durationMs, velocity 1–127, pitchHz, source |
| ตำแหน่งพิณ | kind=string-fret, stringIndex, fret |
| ตำแหน่งระนาด | kind=bar, barId |
| การแสดงออก | pitchBend เฉพาะเครื่องที่รองรับ; มือซ้าย/ขวาเป็นข้อมูลเสริม |

ใช้ discriminated union สำหรับ target และตรวจให้ตรงกับ instrumentId ห้ามให้ระนาดต้องกรอก string/fret จำลอง เก็บ pitchHz และ tuning snapshot เพื่อเล่นงานเดิมได้แม้ preset เปลี่ยน การส่งออก MIDI ต้องมีนโยบายแปลงเสียงที่ไม่ตรง semitone พร้อมแจ้งการประมาณค่า

Recording ใช้เวลาเป็นมิลลิวินาที ส่วน Studio ใช้ beat/durationBeats และ BPM แปลงหน่วยที่ขอบเขตเดียวอย่างชัดเจน อย่านำสองหน่วยมารวมใน field เดียว เสียงระนาดอาจมีหางเสียงหลังปล่อยปุ่ม จึงแยกอายุ voice ออกจากระยะเวลาที่กด

เพลงแยกเป็น Song metadata และ Arrangement ซึ่งมี songId, instrumentId, tuningSnapshot และ notes ความก้าวหน้าผูก instrumentId + arrangementId + revision เพื่อไม่ให้การฝึกพิณนับเป็นความสำเร็จของระนาด หรือใช้ความก้าวหน้าเก่ากับแบบฝึกที่เปลี่ยนแล้ว

Studio ใช้ tracks ที่มี instrumentId, volume, muted และ notes แทน phinVolume/phinMuted แต่รุ่นแรกยังเปิดหนึ่งเครื่องต่อโปรเจกต์ได้ ไม่ต้องทำวงดนตรีหลายเครื่องพร้อมกันทันที

## Ranat Next รุ่นแรก

ขอบเขตที่ควรส่งมอบก่อน:

1. หน้าระนาดที่กดด้วยสัมผัสหลายจุด เมาส์ และคีย์บอร์ดได้ พร้อม label โน้ตและ focus ที่มองเห็น
2. เสียงที่เล่นซ้อนและตีซ้ำลูกเดิมได้ แต่ละ strike มี voice id แยก จำกัดจำนวน voice เพื่อคุมทรัพยากร
3. สเกลและชุดเสียงระนาดที่ระบุชัด หากใช้เสียงสังเคราะห์ให้ระบุว่าเป็นเสียงจำลอง
4. เล่นอิสระ ปรับระดับเสียง metronome อัดและฟังย้อนหลัง
5. แบบฝึกไล่เสียง สลับมือ และเล่นตามจังหวะที่จัดสำหรับระนาดโดยเฉพาะ

เลื่อน camera/AR และ Studio เต็มรูปแบบไปหลังจากสัมผัสและเสียงทำงานเสถียร การตีผ่านกล้องต้องมี logic ตรวจ strike, cooldown และการแยกมือ ไม่ใช้เงื่อนไขการดีดพิณตรง ๆ

## การย้ายจากระบบปัจจุบัน

1. เพิ่ม registry กับตัวสร้างเส้นทางกลาง แล้วห่อ Phin ปัจจุบันเป็นโมดูลแรกก่อนเปลี่ยนพฤติกรรม
2. เพิ่มหน้าเครื่องและเมนูจาก registry ตั้ง Phin Next เป็นชื่อแสดงผล เก็บชื่อ Virtual Phin ในคำอธิบาย
3. ย้ายข้อมูลเป็น v2 ผ่าน reader/adapter ที่อ่าน v1 ได้ ข้อมูลเดิมทั้งหมดถือเป็น phin และเก็บ tuning เดิม
4. เพิ่ม Ranat แบบ touch/keyboard ให้ผ่านสัญญาร่วมก่อนเพิ่มบทเรียนและกล้อง

ความเข้ากันได้:

- /songs, /play/[slug], /studio, /takes และหน้ารายละเอียด/ฝึก take เดิมไปเส้นทาง phin ที่เทียบเท่ากัน โดยรักษา slug, id และ query เช่น category=learn; /settings ยังเป็นการตั้งค่าร่วม
- เปลี่ยนหน้า / เป็นหน้ารวมเมื่อพร้อมเปิดเครือ ระหว่างพัฒนาใช้หน้าเลือกเครื่องแยกได้
- ปัจจุบัน practice อยู่ใน localStorage ชื่อ virtual-phin.practice.v1 ส่วน takes อยู่ใน IndexedDB virtual-phin และมี fallback localStorage จึงต้องย้ายทั้งสองช่องทาง ไม่ใช่เปลี่ยน key อย่างเดียว
- migration ต้องทำซ้ำได้โดยไม่สร้างสำเนาซ้ำ อ่าน/ตรวจ/เขียน/อ่านกลับให้สำเร็จก่อนทำเครื่องหมายย้าย เก็บข้อมูลต้นฉบับไว้หาก quota เต็มหรือเขียนไม่ได้
- ห้ามล้าง record เมื่อเจอ instrumentId หรือ schemaVersion ที่ยังไม่รองรับ ให้แสดงว่าเปิดไม่ได้และเก็บต้นฉบับไว้
- การเปลี่ยนชื่อแบรนด์ไม่จำเป็นต้องเปลี่ยนชื่อฐานข้อมูลทันที ใช้ namespace และ instrumentId แยกข้อมูลภายในได้

## เกณฑ์พร้อมใช้งาน

- URL เดิมและข้อมูลพิณ v1 ยังเปิด ฝึก และเล่นย้อนหลังได้
- บันทึกพิณและระนาดไม่ปะปน และ arrangement ชื่อเดียวกันแยกความก้าวหน้า
- การสลับเครื่องไม่ทิ้งเสียง กล้อง listener หรือ recording ที่ทำงานค้าง
- ระนาดตีสองลูกพร้อมกันและตีลูกเดิมซ้ำได้ ไม่มีเสียงค้างเมื่อเสีย focus
- หน้าระนาดไม่ดาวน์โหลดชุดเสียง/กล้องของพิณโดยไม่จำเป็น
- การย้ายข้อมูลล้มเหลวหรือทำซ้ำไม่ทำให้ข้อมูลเดิมหาย
- ทดสอบ registry/validation, migration v1→v2, timing และ cleanup พร้อมลองบนมือถือจริงก่อนเปิดใช้

เมื่อเพิ่มเครื่องที่สาม งานหลักควรเป็นเพิ่มโมดูล registry entry เสียง พื้นผิวเล่น และ arrangement ของเครื่องนั้น โดยไม่ต้องคัดลอกระบบบันทึกหรือความก้าวหน้าทั้งชุด
