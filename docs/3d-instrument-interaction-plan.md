# แผนโมเดล 3D และ interaction สำหรับ Hackathon

วันที่: 2 ตุลาคม 2026 — ข้อเสนอสำหรับพัฒนาต่อ ยังไม่ได้สร้างโมเดลหรือเปลี่ยนหน้าเว็บ

## แนวคิด

เครื่องดนตรีไทยที่มีชีวิต: สร้างพิณและระนาดเอกเป็นโมเดลของโปรเจกต์เองใน Blender มี silhouette ที่จดจำได้ วัสดุไม้โทนอุ่น โลหะด้าน และรายละเอียดไทยเฉพาะจุด ใช้ภาพอ้างอิงที่ผู้ใช้แนบเป็นแนวทางจัดวางหน้า showcase พื้นหลังอ่อน เงานุ่ม และพื้นที่ว่างมาก โมเดลสีจริงแบบลดความอิ่มสีจะช่วยเห็นมิติโดยไม่แย่งข้อความ

ใช้ต้นฉบับ Blender หนึ่งชุดต่อเครื่อง และ GLB สำหรับเว็บ แยกคุณภาพส่งออกได้ภายหลัง แต่รักษาชื่อชิ้นส่วนและ target ID เหมือนกันทุกโหมด การสร้างใหม่ต้องอ้างอิงรูปทรงเครื่องดนตรีอย่างเหมาะสม บันทึกที่มาของ reference และ texture ไม่ถือว่าภาพสองมิติเป็นโมเดลพร้อมเล่น

## สิ่งที่ตรวจพบในโปรเจกต์

- Next 16.3 และ React 19.2 มีระบบเสียงและ input อยู่แล้ว ยังไม่มี dependency ของ Three.js หรือ React Three Fiber
- พิณมี 3 สาย และพื้นที่เล่น 7 ตำแหน่งต่อสาย รวม 21 เป้าหมายใน TouchPhinControls; เสียงผ่าน usePhinAudio และการเล่น/ฝึกผ่าน VirtualPhinStudio
- ระนาดมี 21 ลูกใน src/instruments/ranat/model.ts และระบบตีเดี่ยว ตีคู่ กรอ รัว บันทึก และ playback ใน useRanat
- ระนาดใช้การเทียบเสียงจำลอง equal-seven-a3-v1 อย่าเปลี่ยนเสียงตามรูปทรงโมเดลหรืออ้างว่าเป็นเสียงเครื่องจริง
- โหมดกล้องพิณใช้วิดีโอ canvas และ MediaPipe; มีการปรับ HUD และพื้นที่ดีดอยู่แล้ว
- ระนาดมีตัวตรวจ strike ผ่านกล้องใน camera.ts การมีไฟล์นี้ไม่ได้ยืนยันคุณภาพการเล่นจริงบนทุกอุปกรณ์
- หน้าในภาพอ้างอิงเป็นหน้ารวมเครื่องดนตรี ควรตรวจ route /instruments ก่อนเริ่มแก้ ไม่สมมติว่าเป็นหน้า / ซึ่งปัจจุบันแสดง HomeDashboard

## ชิ้นส่วนโมเดลและเป้าหมายเล่น

### พิณ

- root: phin_root; body, neck, head, bridge เป็นชิ้นหลัก
- สาย: string_0, string_1, string_2 แยก mesh เพื่อทำ vibration
- fret marker ตามโครงสร้างจริง แยกจากเป้าหมายเล่นของ UI; 7 ตำแหน่งของแอปไม่จำเป็นต้องเท่าจำนวนเฟรตทั้งหมดบนโมเดล
- hit target ที่มองไม่เห็น: phin_hit_s0_f0 ถึง phin_hit_s2_f6 ใช้ string/fret เป็น ID ถาวร
- เฟรตที่เลือกใช้ overlay highlight โดยไม่ทำให้ตัวคอพิณยืดหรือบิด
- สายสั่นแบบลด amplitude ตามเวลาเพื่อสื่อการดีด ไม่พยายามจำลองความถี่เสียงด้วยเฟรมภาพ

### ระนาดเอก

- root: ranat_root; trough, base, end ornaments เป็นชิ้นคงที่
- ลูก: bar_00 ถึง bar_20 เรียงตาม ID ของแอป ตรวจตำแหน่งเสียงต่ำ/สูงกับการแสดงผลก่อน export
- mallet_L, mallet_R มี pivot สำหรับการตี; ลูกมี pivot ของตัวเองสำหรับการสั่นที่เล็กมาก
- hit target: ranat_hit_00 ถึง ranat_hit_20 ขยายพื้นที่รับสัมผัสได้โดยไม่ขยายรูปร่างลูก
- ใช้ไม้ตีสองชิ้นเดิมสำหรับกรอ/รัว หาก event เร็วกว่า animation ให้ retarget และรักษาเวลาจังหวะ ไม่ต่อคิว animation จนค้าง

ไม่ต้อง rig แบบตัวละครทั้งเครื่อง ชิ้นส่วนแยกและ pivot เพียงพอสำหรับต้นแบบ ชุดท่าคงที่ เช่น showcase sway หรือไม้พัก ทำเป็น clip ได้; การตีโน้ตและสั่นสายควบคุมตาม event ระหว่างเล่น

## โครงสร้าง interaction

Touch / keyboard / camera / playback → แปลเป็น target ดนตรี → runtime เครื่องเดิม → เสียง + visual event + recorder

โมเดลเป็นผู้รับ visual event ไม่สร้างโน้ตซ้ำจากจังหวะที่ไม้ชน ลูกระนาด หรือ animation callback ใช้ clock เสียงเดิมสำหรับเหตุการณ์ที่นัดล่วงหน้า ทั้งเสียงและภาพควรอ้าง event ID เดียวกัน

Visual event เป้าหมาย: eventId, instrumentId, target (string/fret หรือ barId), velocity, hand ถ้ามี, เวลาเสียง, source ข้อมูลนี้เป็น adapter ภายในก่อน ไม่เปลี่ยน schema บันทึกทั้งหมดเพียงเพื่อเพิ่ม 3D

- พิณ: จุดเชื่อมอยู่ที่การดีดสำเร็จใน VirtualPhinStudio; วาง visual event ใกล้เวลานัดเสียงในขั้นพัฒนาจริง
- ระนาด: ต่อจาก emit/เวลานัดเสียงใน useRanat; อย่าใช้ hits state อย่างเดียวเป็น event bus เพราะข้อมูลรวมตามมืออาจทำให้โน้ตใกล้กันหายจากภาพ
- pointer ใช้ pointerId แยกนิ้ว; จบเสียง/รูปแบบค้างเมื่อ pointercancel, keyup, blur และเปลี่ยนโหมด
- ระดับแรงคงที่หรือเลือก preset สำหรับอุปกรณ์สัมผัสทั่วไป ไม่อ้างว่าอ่านแรงกดได้ทุกเครื่อง
- มือจากกล้องขาดหาย: ยกเลิกคำสั่งค้างและกลับท่าพัก; การกลับมาตรวจพบไม่ควรสร้างเสียงเอง
- กล้อง mirrored และ object-cover ต้องแปลงพิกัดด้วยระบบเดิมก่อนหา target มิฉะนั้นมือกับภาพเครื่องจะเหลื่อม
- สำหรับคอพิณเล็กบนมือถือมีปุ่มโน้ต 2D ขนาดใช้งานได้ควบคู่กับภาพ 3D; ไม่บังคับให้กดเส้นสายเล็ก ๆ

## เทคโนโลยีที่เสนอ

ใช้ Three.js ผ่าน React Three Fiber เพื่อให้หน้า React ใช้ renderer และ instrument scene ร่วมกัน เสนอเป็น dependency ใหม่ ยังไม่ได้ติดตั้ง ใช้ GLTFLoader สำหรับ GLB และ DOM สำหรับปุ่ม/label/การเข้าถึงด้วยคีย์บอร์ด

แยก InstrumentScene (แสดงโมเดลและรับ event), ShowcaseScene (มุมแสดงสินค้า), PlayScene (มุมเล่นและ hit target), CameraOverlayScene (พื้นหลังโปร่งใสเหนือวิดีโอ) แชร์ geometry/material ที่โหลดแล้วแต่แยก instance และสถานะ animation

หน้า showcase เริ่มด้วยภาพ poster โหลด 3D เมื่อการ์ดเข้า viewport และหยุด render เมื่อออก viewport ถ้ามีสองเครื่องใช้ canvas เดียวกับสองพื้นที่แสดงผล หรือโหลดเฉพาะการ์ดที่ active เพื่อลด context บนมือถือ ถ้า renderer ล้มเหลว ให้ภาพและปุ่ม 2D ใช้งานต่อได้

AR แบบวางบนพื้นผิวใช้ WebXR เป็นงานอีกระยะ ตรวจ immersive-ar/hit-test บนอุปกรณ์จริงก่อนสัญญาว่ารองรับ นำโมเดลไปดูผ่าน native AR viewer ได้เป็นทางเลือก แต่ความสามารถดูโมเดลใน AR ไม่ยืนยันว่าปุ่มเว็บ/MediaPipe จะเล่นเครื่องต่อได้ใน native viewer

ก่อนเขียน integration ใน Next ต้องอ่านคู่มือที่ติดตั้งใน node_modules/next/dist/docs ตาม AGENTS.md โดยเฉพาะ client boundary และ lazy loading

## เป้าหมาย performance เริ่มต้น (ต้องวัดจริง)

- ไม่เกินประมาณ 40k triangles ต่อเครื่อง; GLB ตั้งเป้า 2–4 MB ต่อเครื่อง
- ใช้วัสดุร่วม 4–6 ชุด texture หลัก 1024; รายละเอียดแกะสลักใช้ normal map เมื่อเหมาะสม
- ขนาดและหน่วยเป็นเมตร มี root origin และทิศทางตกลงร่วมกัน บันทึกขนาดจริงเป็น metadata แยกการ scale ในหน้าเว็บ
- ใช้ material ที่ส่งออก GLB ได้ ลด shader เฉพาะ Blender และ bake รายละเอียดที่จำเป็น
- mobile pixel ratio จำกัดประมาณ 1–1.5 เริ่มแบบไม่มี postprocessing หนัก
- ตั้งเป้าเล่นบนมือถือ 30 fps ขึ้นไป; desktop 60 fps เป็นเป้าหมาย ไม่ใช่ผลวัด
- ความเร็วเสียงต้องไม่ผูกกับ fps ของ 3D; วัดตั้งแต่ input ถึงเสียงบนเครื่องเดโมจริง
- export → ตรวจชื่อ/pivot/scale → optimize โดยรักษา target IDs → โหลดกลับในเว็บเพื่อยืนยัน

## ลำดับทำสำหรับ Hackathon

1. ทำระนาด blockout ก่อน: ราง 21 ลูก และสองไม้ ตรวจ silhouette กับ mapping จริง ข้อดีคือมีจุดตีชัดและระบบ event เดิมพร้อมต่อ
2. ทำหนึ่งเส้นทางครบ: แตะ/คีย์บอร์ด → เสียงเดิม → ไม้ตีและ highlight → อัด → playback ขยับตามทุกโน้ต
3. เพิ่มวัสดุและแสง แล้วใช้ GLB เดียวใน showcase รักษาตำแหน่งข้อความ/ปุ่มตามภาพอ้างอิง
4. ทำพิณ blockout: body/neck/head/3 สาย ติด target คอพิณและ animation ดีด
5. ใช้โมเดลในโหมดกล้องเดิม ทดสอบ mirrored view, จัดพื้นที่เล่น และ loss of tracking
6. ถ้าเวลาและเครื่องเดโมรองรับ จึงทดลองวางบนโต๊ะด้วย WebXR; ส่งมอบ camera overlay ที่พร้อมใช้งานได้แม้ขั้นนี้ยังไม่เสร็จ

ประมาณการเพื่อจัดลำดับเท่านั้น: ระนาดครบเส้นทาง 1 วัน; พิณและ showcase อีก 1 วัน; โหมดกล้อง/ปรับมือถืออีก 0.5–1 วัน ขึ้นกับความละเอียดโมเดลและข้อผิดพลาดเดิม ยังไม่ทราบวันส่งงานหรือจำนวนคน

## เกณฑ์พร้อมเดโม

- แตะสองนิ้ว/เล่นหลายโน้ตได้ตามความสามารถ runtime เดิม ไม่เกิดโน้ตซ้ำจาก 3D
- เปลี่ยนช่วงคีย์บอร์ดแล้ว target ที่ขยับตรงกับเสียงและข้อมูลบันทึก
- ฟังบันทึกย้อนหลังแล้วไม้/สายตอบสนองทุก event รวมตีคู่ กรอ และรัว
- ขณะเล่น gesture ไม่หมุนกล้องโดยบังเอิญ; เมื่อออกจากหน้าไม่เหลือเสียง/กล้อง/งาน render ค้าง
- showcase มี motion แบบเงียบ ไม่เปิดกล้องเอง และมีภาพสำรองระหว่างโหลด
- ตรวจโทรศัพท์เดโมจริงทั้งแนวตั้ง/แนวนอน; การปฏิเสธกล้องและ WebGL ที่ใช้ไม่ได้ยังเปิดโหมด 2D ได้
- AR surface แสดงให้กรรมการเห็นได้เฉพาะเมื่อทดสอบแล้วบนอุปกรณ์ที่ใช้จริง
