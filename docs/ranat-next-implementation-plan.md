# Ranat Next — แผนส่งมอบ

## ผลลัพธ์และขอบเขต

เพิ่มเครื่องระนาดในเครือเดียวกับ Phin ด้วย design tokens เดิม: พื้นเทาอ่อน ปุ่มนูน มุมมน typography เดิม และสีอำพันเฉพาะเครื่อง ไม่เปลี่ยนข้อมูล/งาน AR พิณที่กำลังแก้อยู่

## ลำดับงาน

1. Registry เครื่องและหน้าเลือกเครื่อง: metadata, สถานะ, routes; Phin ใช้ระบบเดิม
2. แกนระนาด: 21 ลูก tuning ทดลอง, event กลาง, pair bounds, direct/pair/kro/roll และ scheduler เดียวสลับสองไม้
3. ผิวเล่น: ระนาดวาดด้วย SVG ในมุมคนเล่น รับหลาย pointer และ keyboard, แสงตอบสนองและไม้เสมือน, จอเล็กขยายช่วงเสียง
4. เสียง: synth ที่ระบุว่าเสียงจำลอง, polyphony, volume, stop/dispose และป้องกันเสียงค้าง
5. ประสบการณ์ครบวงจร: demo สั้น, คำอธิบายเทคนิค, tempo/กรอ, metronome, อัด/ฟัง/ดาวน์โหลดและเก็บ take ในเบราว์เซอร์
6. กล้องทดลอง: โหลดระบบจับมือเมื่อเปิดเท่านั้น, สอบเทียบขอบและแนวตี, ไม่มี wide ใช้ช่วงเสียงแคบ, hold สำหรับกรอช่วย, หลุดกรอบหยุดเสียงใหม่
7. ตรวจ: unit tests ของ pattern/bounds/calibration, typecheck/lint/build และลอง UI desktop/mobile ด้วยเบราว์เซอร์

## เกณฑ์ตรวจ

- เข้าได้จากหน้าเดิมและหน้า /instruments; ชื่อ Phin Next / Ranat Next อยู่ในเครือเดียวกัน
- multi-touch สร้างโน้ตอิสระ; keyboard ไม่ repeat จากการค้างใน direct
- คู่แปดไม่ล้นราง; กรอ L/R ไม่ใช้ timer แยกและไม่สร้างคู่ซ้ำจากสอง pointer
- ยกเลิก pointer, blur, ซ่อนแท็บ, เปลี่ยนโหมด และ unmount หยุด generator เสมอ
- take บันทึกโน้ตที่เกิดจริงพร้อม assistance metadata; อ่านข้อมูลเสียไม่ทำหน้าใช้งานไม่ได้
- หน้าเล็กไม่ล้นแนวนอน ปุ่มควบคุมเข้าถึงได้ด้วย keyboard
- กล้องระบุทดลอง; ไม่มีการรับรองความแม่นจากการทดสอบจำลองเท่านั้น

## งานที่ต้องตรวจด้วยอุปกรณ์/ผู้เชี่ยวชาญภายหลัง

ชุดเสียงระนาดจริงและ tuning ที่ครูตรวจ, motion-to-sound บนมือถือ, การตีรัวเร็วและมือไขว้, tracking worker, บทเรียนและคะแนนตามทางเพลง, migration studio หลายเครื่อง สิ่งเหล่านี้ไม่แสดงเป็นความสามารถพร้อมใช้ก่อนผ่านการตรวจ

## สถานะการลงมือ

- ทำแล้ว: registry, หน้าเลือกเครื่อง /instruments, Phin Next branding และหน้า Ranat Next
- ทำแล้ว: ระนาด SVG 21 ลูก มุมคนเล่น ใช้สี/เงา/ตัวอักษรเดิม ขยายพื้นที่เล่นเป็น 8 ลูกได้
- ทำแล้ว: สัมผัส คีย์บอร์ด ตีคู่หลายช่วง รวมคู่แปด กรอช่วยและรัวเสียงเดียว เลือกความดัง/ความเร็วแยกกัน
- ทำแล้ว: เสียงสังเคราะห์แบบ modal ใน tuning ทดลอง 7 ขั้นเท่ากันต่อ octave; ยังไม่ใช่ sample เสียงจริง
- ทำแล้ว: metronome, demo, บันทึก musical events, ฟังย้อนหลัง, เก็บ localStorage, ส่งออก WAV/JSON และนำเข้า JSON
- ทำแล้วในสถานะทดลอง: โหลด tracking เฉพาะเมื่อเปิดกล้อง สอบเทียบ 4 ตำแหน่ง กล้องธรรมดาควบคุม 8 ลูก และ watchdog หยุดเมื่อข้อมูลมือหาย
- ทำแล้วในสถานะทดลอง (20 ต.ค.): โหมด AR ซ้อนภาพกล้อง — ระนาด 3D วางบนวิดีโอ จัดตำแหน่งได้ พื้นที่เล่นคำนวณจากตำแหน่งลูกที่วาดจริง ใช้ controller/runtime เดิม ([ออกแบบ](./ranat-ar/system-design.md))
- ทำแล้ว (20 ต.ค.): โมเดลเว็บ ranat-modern-v6.glb 3.7 MB จาก 9.0 MB ด้วย scripts/optimize-ranat-web.py โดยไม่แตะลูก/ไม้ตี
- ยังต้องทำ: stable track identity แทน handedness ในกล้อง, worker inference, การสอบเทียบสถิติหลายเฟรม, validation ความแม่น Full 21 และบทเรียนที่ครูตรวจ

## แผนระยะถัดไปพร้อมเกณฑ์จบ

### A. ยืนยันคุณภาพเสียงและประสบการณ์พื้นฐาน

จัดหา samples ที่มีสิทธิ์ใช้ ระบุ pitch ต่อ bar และ soundSetVersion; ทดสอบเสียงสองไม้พร้อมกัน/รัวแล้วไม่ clip; ครูตรวจการตั้งเสียง ความสมดุล และการใช้ชื่อเทคนิค เกณฑ์จบคือฟังเทียบ direct, pair, kro, roll และยอมรับได้ทั้งลำโพง/หูฟัง

### B. ทำกล้องให้พร้อมใช้จริง

ต่อจาก UI สอบเทียบที่ทำแล้ว เก็บหลายเฟรมและ jitter, สร้าง trackId ด้วย continuity, หยุดเมื่อมือไขว้กำกวม, แยก worker และทดสอบ CPU fallback ตรวจกล้องหน้า/หลังบน iOS Safari และ Android Chrome พร้อมมือหนึ่ง/สองข้าง แสงน้อยและหลุดเฟรม เกณฑ์ตามเอกสารระบบละเอียด: accuracy ≥90%, duplicate ≤1%, false strike ≤1/นาทีในชุดทดสอบ และวัด motion-to-sound จริง

### C. บทเรียนและการประเมิน

สร้าง arrangement เฉพาะระนาด: ตีเดี่ยว → สลับ → คู่แปด → กรอ; ใช้ technique metadata แยกคะแนน assisted กับ direct และหยุดนับคะแนนเมื่อ tracking ขาด ก่อนส่งมอบต้องให้ครูตรวจทำนอง จังหวะ ชื่อโน้ต และคำแนะนำ

### D. แพลตฟอร์มหลายเครื่องเต็มรูปแบบ

ย้าย Phin เป็น adapter ที่เข้ากับ event กลางโดยอ่าน take v1 เดิมได้ เพิ่ม arrangementId/revision และ storage migration แบบไม่ทำลายต้นฉบับ จากนั้นรวม library และ Studio tracks; ทดสอบเปิดงาน Phin เก่าและสลับเครื่องโดยข้อมูล/เสียงไม่ปะปน จึงค่อยเพิ่มเครื่องที่สาม

## หลักฐานตรวจรุ่นแรก

ทดสอบ UI จริงบน viewport desktop และ 390px: แตะ 2 โน้ตได้ 2 events, คู่แปด 1 ครั้งได้ 2 events, A/S/D ได้ 3 events, กดค้างกรอได้ L bar4 / R bar11 ห่างกัน 100ms และไม่ตีต่อหลังปล่อย, บันทึกอยู่หลัง reload และเล่นย้อนหลังได้ ดาวน์โหลด WAV ได้ไฟล์ RIFF/WAVE 22050Hz และนำเข้า JSON เดิมได้โดยไม่สร้างรายการซ้ำ

กล้องตรวจเฉพาะการโหลดหน้าตั้งค่าและ logic ผ่าน unit tests ยังไม่ได้เปิดกล้องจริงหรือวัด latency/ความแม่นบนมือถือ การตรวจจอแคบด้วย viewport ไม่ใช่การทดสอบอุปกรณ์มือถือจริง
