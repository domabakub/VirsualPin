# Virtual Phin — การแก้ UX/UI หลัง audit

แก้ใน local working tree วันที่ 31 สิงหาคม 2026 ไม่มีการ deploy หรือ commit และรักษางานเดิมด้าน hand tracking กับเสียง Safari ไว้

## สิ่งที่แก้

| Audit | การแก้ในรอบนี้ |
|---|---|
| A01 โน้ตไม่ตรงเสียง | ใช้ tuning ร่วม E4 / A3 / E3 คำนวณ label จากสาย/เฟรตหลังแปลงแบบฝึกแล้ว ทั้งเสียงและ UI ใช้ข้อมูลเดียวกัน ระบุชัดว่าเป็นแบบฝึกทดสอบ ไม่ใช่ทำนองต้นฉบับที่ตรวจสอบแล้ว |
| A02 หน้าฝึกล้นและปุ่มเริ่มไกล | จัดโน้ตปัจจุบันกับเริ่ม/พักไว้ด้านบน ใช้ตัวเลือกเฟรตและปุ่มดีดขนาดอย่างน้อย 44px มือถือซ่อนภาพพิณเมื่อกล้องปิด; เมื่อกล้องเปิด ย้ายภาพขึ้นใกล้โน้ตและคงปุ่มหน้าจอไว้ |
| A03 ความคืบหน้าจำลอง | นำตัวเลขจำลองออก บันทึกคะแนน ความคืบหน้า และค่าตั้งใน localStorage แบบมีเวอร์ชัน รองรับข้อมูลเสียและกรณีเขียนไม่ได้ด้วยข้อมูลชั่วคราวพร้อมคำเตือน |
| A04 เมนูและตัวกรอง | active เมนูเพียงรายการเดียวและใช้ aria-current ตัวกรองอยู่ใน URL หน้า “พื้นฐาน” มีคำแนะนำเริ่มต้นและกรองแบบฝึกพื้นฐาน |
| A05 ค้นหาและโฟกัส | เพิ่ม label ถาวรให้ช่องค้นหา เส้นโฟกัสคีย์บอร์ด และ skip link ไปเนื้อหาหลัก พร้อม empty state และทางล้างตัวกรอง |
| A06 ข้อความจาง | ใช้ข้อความเข้มบนพื้นอ่อน ข้อมูลสำคัญไม่ใช้ตัวอักษร 8–10px แบบเดิม overlay กล้องใช้พื้นเข้มและข้อความขาว |
| A07 สถานะที่เข้าถึงได้ | เลือกเฟรตด้วย native select ใช้ native progress, status/alert สำหรับผลฝึกและข้อผิดพลาด พร้อมสถานะเมโทรนอมและโฟกัสสรุปผล |
| A08 ตั้งค่าไม่ทำงาน | แทนปุ่ม profile เดิมด้วยลิงก์ตั้งค่า กล้องเริ่มต้น ระดับเสียง และปุ่มลัดบันทึกได้จริง แสดงตรงไปตรงมาว่ายังปรับความไวการตรวจมือไม่ได้ |
| A09 ขั้นตอนเริ่มและกล้อง | อธิบายการเล่นโดยไม่ใช้กล้อง แยกสถานะรอสิทธิ์/โหลดโมเดล/พร้อม/ผิดพลาด มีหยุดและยกเลิก พร้อมป้องกัน stream ที่มาถึงหลังยกเลิก |
| A10 พัก/เล่นต่อ/จบ | พักและเล่นต่อไม่ล้างคะแนน มีสรุปเมื่อครบ ปุ่มไปแบบฝึกถัดไป และยืนยันก่อนเริ่มใหม่ โหมดอิสระไม่แสดงคะแนนจำลอง |
| A11 รูปแบบไม่สม่ำเสมอ | ใช้สี ปุ่ม แผงเนื้อหา โฟกัส และระยะห่างร่วมกัน การ์ดเพลงกดได้ทั้งใบ ไม่มีปุ่มซ้อนลิงก์ รองรับ reduced motion |

## ผลตรวจ

- `npm test`: ผ่าน 8 รายการ ครอบคลุม pitch ทั้ง 21 ตำแหน่ง, โน้ตของทุกแบบฝึก, คะแนนถูก/ผิด/จบ, serialization, ข้อมูลเสีย และการบันทึกไม่ได้/กลับมาบันทึกได้
- `npm run lint`, `npm run typecheck`, `npm run build`: ผ่าน
- ทดลองฝึกลาวดวงเดือนครบ 12 โน้ต มีผิด 1 ครั้ง ได้ 1,200 คะแนน / 92% และคลังเพลงแสดงฝึกครบแล้ว จากนั้นทดสอบยกเลิกการเริ่มใหม่ ผลยังครบ 12; กดยืนยันแล้วกลับ 0 และ reload ยังคง 0
- พักแล้วดีดไม่เพิ่มความคืบหน้า โหลดใหม่แล้วฝึกต่อจากโน้ตเดิมได้
- โหมดอิสระ: สาย 1 เฟรต 2 แสดง F♯4 ตรงกับ mapping และไม่ให้คะแนน
- เปลี่ยนกล้องเริ่มต้นกับปุ่มลัดแล้ว reload ค่ายังคงอยู่ ระดับเสียงผ่านปุ่มลด 80% → 75% แล้ว reload ยังคง 75%; คืนค่าทดสอบทั้งหมดเป็นกล้องหน้า เสียง 80% ปุ่มลัดปิด
- ตัวกรองเพลงไทยเดิมให้ 3 แบบฝึกและอยู่หลัง reload; กลับจากพื้นฐานเป็นคลังได้ 6 แบบฝึก ค้นหาไม่พบแล้วล้างได้
- ตรวจ keyboard focus ช่องค้นหา: `:focus-visible` และ outline สีน้ำเงิน 3px
- ตรวจ 6 เส้นทางที่ความกว้าง 320, 390, 768, 1280px: document scrollWidth เท่ากับ clientWidth ทุกกรณี ไม่มีการเลื่อนแนวนอน แต่ละหน้ามี main landmark เดียว ดู [ข้อมูลวัด](./responsive-checks.json)
- หน้าฝึก 320px: ปุ่มเริ่มอยู่ประมาณ y=155px สูง 44px และปุ่มดีดครบ 3 สายอยู่ในจอแรก ต่างจากก่อนแก้ที่ปุ่มเริ่มอยู่ต่ำกว่า 1,000px บนมือถือ
- เปิดดูภาพจริงจาก production build ใน Chromium และไม่พบ console error ในรอบตรวจ

## ข้อจำกัดก่อนเผยแพร่

- ยังไม่ใช่การรับรอง WCAG 2.2 AA: ต้องตรวจ screen reader จริง, zoom 200%, ความต่างสีทุกสถานะ และอุปกรณ์จริงเพิ่มเติม
- ไม่ได้เปิดกล้องหรืออนุญาตสิทธิ์ใหม่ จึงยังไม่ยืนยัน tracking จริงบนมือถือ, iPad หรือ Safari การยกเลิกกล้องตรวจจากโค้ด ไม่ใช่เครื่องจริง
- ยืนยันเส้นทางเล่นเสียงผ่านสถานะสำเร็จของ UI และ pitch จากโค้ด ไม่ได้วัดความถี่จากลำโพงหรือฟังยืนยันบน Safari
- การทดสอบระดับเสียงผ่านปุ่มเพิ่ม/ลดและการบันทึกสำเร็จ; การลาก native slider ด้วย browser automation ยังยืนยันไม่ได้ ต้องตรวจ touch/keyboard บนอุปกรณ์จริง
- เพลงยังเป็นข้อมูลทดสอบ ต้องให้ผู้รู้พิณตรวจทำนองและวิธีตั้งสายก่อนนำไปใช้สอนจริง คะแนนประเมินเฉพาะสาย/เฟรต ยังไม่วัดจังหวะ
- ผลฝึกอยู่ในเบราว์เซอร์นี้เท่านั้น ไม่มีบัญชีหรือการซิงก์ และการเริ่มใหม่แทนที่ผลรอบก่อน ไม่ใช่ประวัติหลายรอบ
